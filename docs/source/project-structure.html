1. The repository at a glance

Three independent parts — the contracts, the web app and the Chainlink workflow — share one repository, with documentation and two helper scripts alongside.

GrantLane/
├── contracts/                Solidity: the escrow, the CRE receiver, tests and scripts (Foundry)
│   ├── src/                  Deployed contracts and the interfaces they use
│   ├── test/                 Unit tests, receiver tests, fork tests against live UMA
│   └── script/               Deploy scripts and a step-by-step demo driver
├── apps/web/                 Next.js app: pages, API routes, components, libraries
│   ├── app/                  Routes — pages and API endpoints
│   ├── components/           React components
│   └── lib/                  Chain access, UMA, World ID, storage, helpers
├── cre-workflow/             Chainlink CRE project
│   └── settlement-workflow/  Cron workflow that settles expired claims

2. contracts/

A Foundry project, Solidity 0.8.24 with OpenZeppelin 5.1. Dependencies live in contracts/lib/ and are installed, not committed.

src/ — what is deployed

FileResponsibility
GrantEscrow.solThe escrow. Funds grants, turns milestone claims into UMA assertions with a USDC bond, receives UMA's callbacks, credits approved payouts for withdrawal, exposes permissionless settlement and Automation-style upkeep, and verifies the EIP-712 Selfie Check attestations for claims and payout-wallet changes.
automation/SettlementReceiver.solReceives the CRE workflow's report and forwards it to GrantEscrow.performUpkeep. Can call nothing else.
automation/ReceiverTemplate.solBase for CRE receivers: accepts reports only from the configured forwarder, optionally only from an expected workflow owner or name.
automation/IReceiver.solThe report-receiving interface CRE's forwarder calls.
interfaces/IOptimisticOracleV3.solThe subset of UMA's oracle the escrow calls.
interfaces/IOptimisticOracleV3CallbackRecipient.solThe callbacks UMA makes when a claim is disputed or resolved.
interfaces/AutomationCompatibleInterface.solcheckUpkeep / performUpkeep, the upkeep interface the workflow drives.

GrantEscrow's external functions

FunctionWhoWhat it does
createGrantGrantorEscrows the full total and commits the terms hash.
submitMilestoneGranteeChecks the attestation, pulls the bond, asserts the claim on UMA.
settleAnyoneSettles a claim whose window closed or whose dispute is answered.
withdrawPayout walletSends everything credited to the caller.
assertionResolvedCallbackUMA onlyApproves and credits, or rejects and reopens.
assertionDisputedCallbackUMA onlyMarks the milestone Disputed.
checkUpkeep / performUpkeepAnyone / CREFinds and settles expired, undisputed claims in batches of up to 10.
changePayoutWalletGranteeRepoints payouts, gated on a Selfie Check attestation.
closeGrantGrantorRefunds unreleased funds; refused while a claim is open.
setAttestorOwnerReplaces the attestor address.
getGrant, getMilestones, awaitingSettlementAnyoneViews the app reads.

test/

FileWhat it proves
GrantEscrow.t.sol45 unit tests: funding, claims, attestations, undisputed and disputed paths, callbacks, withdrawals, closing, upkeep, payout-wallet changes.
mocks/MockOptimisticOracleV3.solA mock oracle that follows UMA's bond and callback rules, for the unit tests.
SettlementReceiver.t.sol8 tests: forwarder and author checks, pass-through of performData, forwarder switch.
GrantEscrow.fork.t.sol7 tests against the real UMA oracle and Circle USDC on a Base Sepolia fork, including disputes and a full upkeep batch within its gas limit.

script/

FilePurpose

A Next.js 14 App Router app in TypeScript, styled with Tailwind on CSS-variable design tokens. Wallet access is wagmi and viem; storage goes through a small key-value layer.

6. Running it

Configuration is documented in .env.example. Copy it and fill in the values before running anything that talks to the chain or World ID.

Web app

npm install --prefix apps/web
npm run dev                  # http://localhost:3001

Contracts

npm run contracts:build
npm run contracts:test       # unit and receiver tests; fork tests run when an RPC is configured

CRE workflow

npm run workflow:typecheck
npm run workflow:simulate    # reads checkUpkeep, reports what it would settle
npm run workflow:broadcast   # the same, sending the settlement on Base Sepolia

After changing the contract

npm run contracts:build
npm run gen:abi              # refresh the web app's ABI

Rebuilding this documentation

cd docs/source
npm install
npm run build                # writes the PDFs into docs/

Foundry, Bun and the CRE CLI are Linux-first; on Windows the root commands run them under WSL.
